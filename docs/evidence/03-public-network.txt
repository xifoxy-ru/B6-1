B6-1-010 퍼블릭 네트워크 실제 실행 증빙
리전: ap-northeast-2 / 프로필: b6-1-iam
계정/ARN/인증 URL/토큰은 보존하지 않았다. STS는 메모리에서 기대 IAM 사용자·계정 일치를 검사하고 마스킹 결과만 기록했다.
초기 sandbox STS exit255는 endpoint 연결 실패로 분류했고, 네트워크 접근 escalation 후 STS와 VPC 검증을 통과했다. 로그인 재실행/프로필 변경은 없었다.

사전 검사: 기존 VPC CIDR/태그/소유계정 일치. VPC 서브넷 0개로 CIDR 겹침 없음; task-tag IGW/RT 각각 0개. 가용 표준 AZ 중 우선값 ap-northeast-2a 선택.
생성: subnet-0e41cb6e4d3caab77 / 10.0.1.0/24 / ap-northeast-2a / available
IGW: igw-0d883adc5de5d57a9 → vpc-010aff9ac6af6adce attachment available
별도 RT: rtb-0b3393b9c2325fdf6 / local active + 0.0.0.0/0 → IGW active
명시 association: rtbassoc-04e52ed126ae95029 → 위 subnet
세 자원 생성 시 Project=B6-1 및 각각 Name=b6-1-public-subnet/b6-1-igw/b6-1-public-rt 태그를 원자적으로 지정했다.
각 create/attach/create-route/associate는 동일 인자의 DryRunOperation(exit254) 확인 후 실제 명령을 한 번 실행(exit0)했다. 정확한 UTC/안전한 인자/최소 응답 필드는 동봉 JSON을 따른다.
기존 main RT/SG/NACL은 수정하지 않았다. EC2/NAT/EIP/IPv6/삭제 작업은 하지 않았다.
MapPublicIpOnLaunch=false를 그대로 유지했다. IGW 기본 경로가 public subnet을 구성하며, 자동 public IPv4 할당 여부는 별개다. 후속 EC2 실행 시 --associate-public-ip-address를 별도 승인 범위에서 지정할 예정이다.
현재 단계에서 사용자가 직접 해야 할 추가 조작은 없다. EC2/보안그룹/키 페어/외부 HTTP 및 EC2 outbound curl 검증은 후속 단계이며 아직 실행하지 않았다.
스크린샷은 촬영하지 않았다. 아래 CLI 최소 필드 증빙으로 확인했다.
