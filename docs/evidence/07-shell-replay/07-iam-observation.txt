사용자 제공 개인정보 마스킹 캡처 관측 — pristine unedited-native라고 주장하지 않는다.
Worker가 실제 view_image로 검토한 사용자 권한 탭: 검색어 없음/모든 유형/권한정책(2), b6-1 고객관리형 직접 연결 + SignInLocalDevelopmentAccess AWS관리형 직접 연결. 화면의 이 목록에는 AdministratorAccess가 없다. 권한 경계 미설정, 콘솔 액세스는 MFA 없이 활성화됨, 액세스 키1(개수만) 표시. 키 값/계정/ARN은 기록하지 않는다. 기존 계정/root/Builder MFA와 이 IAM사용자의 MFA는 구별한다. IAM/MFA/키/정책 설정은 변경하지 않았다.
로컬 policies/b6-1-all-in-one.json 정적 확인: EC2 read/manage 두 Allow는 Resource*+Seoul RequestedRegion; Budget ViewBudget/ModifyBudget와 notifications-contacts Create/List/Get/SendActivationCode/ActivateEmailContact는 Resource*·리전조건 없음. PM이 전달한 사용자 JSON 의미 요약과 이 구조/행동그룹은 일치한다. 사용자가 붙여넣은 원문 JSON 바이트는 이 Worker 입력으로 전달되지 않아 byte-for-byte equality는 주장하지 않는다.
이 화면만으로 모든 유효 정책/다른 경로 권한·최소권한을 증명하지 않는다. 서울 내 다른 EC2자원도 허용하는 넓은 정책이며 전체 least-privilege PASS가 아니다. 후속 사용자 제공 마스킹 캡처 07-iam-mfa.png를 실제 검토: 같은 사용자의 콘솔 액세스가 "MFA로 활성화됨"으로 표시된다. 사용자 MFA 등록 완료 보고와 화면 상태를 기록하며, 기기 종류/개수·재로그인 테스트·API access key에 MFA 강제·정책 MFA조건 추가는 주장하지 않는다. 이전 MFA미설정 화면은 당시 상태로 보존했다.
